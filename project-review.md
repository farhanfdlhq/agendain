# Project Review

Perform a comprehensive review of this entire project as a Principal Full Stack Engineer specializing in Next.js, React, TypeScript, Tailwind CSS, Prisma, and modern web application architecture.

First, understand the project structure, architecture, technologies, coding conventions, and overall design before making any recommendations.

Review the project holistically instead of reviewing individual files in isolation.

Evaluate the project from the following perspectives:

- Project structure
- Folder organization

- Maintainability
- SOLID principles

- Convention over configuration

# Reporting Requirements

Provide findings using the following priority levels:

- Critical
- High
- Medium
- Low
- Informational

For every finding include:

- Title
- Severity
- Location
- Description
- Why it matters
- Recommendation
- Expected impact

---

# Important Rules

Do not rewrite the entire project.

Do not generate unnecessary refactors.

Recommend changes only when they provide measurable improvements.

Prefer built-in framework features before introducing new libraries.

Always explain the reasoning behind each recommendation.

If additional context is needed before making a recommendation, state the assumption clearly.

Begin by understanding the project architecture before reviewing implementation details.
